# FRONTEND_DESIGN · 「合订本」× 轻科技 · 定制组件基准

> **状态**：基准契约（2026-08-29 v2，按用户澄清修订——"AI 味"指**组件太通用、一眼看出是 AI 批量生成**，而非风格家族问题。印刷品/报刊方向与圆角、阴影、轻科技精致感**都保留**）。
> 所有新视图（/stream、/company、/company/[id]）与旧组件改造都必须遵循本文；实现与本文冲突时，改实现而不是改本文。修改本文需在 commit message 中显式声明。

## 1. 诊断：什么让组件"一眼 AI 造"

问题不是某种风格，而是**默认件原样堆砌**——任何 AI 生成的页面都会原样出现这些东西：

| 通用件（要消灭） | 具体表现 |
|---|---|
| 默认卡片脸 | 所有内容都是 `rounded-xl + border + shadow-sm` 的同款盒子，换 logo 就认不出是谁 |
| 默认徽章 | 一切标签都是 `rounded-full` 彩色 pill，圆角+浅底+小字三件套 |
| 默认骨架 | `animate-pulse` 原样灰块，无结构语义 |
| 默认字体与节奏 | Inter/系统栈通吃，全部 `p-6 gap-4`，行高节奏均质 |
| 默认点缀 | emoji 图标、居中空态插画、紫色渐变 hero、"✨"文案 |
| 默认交互 | hover=阴影加深，无焦点态细节，无按压反馈，无定制缓动 |

**保留并强化**（这是产品的身份与质感来源）：印刷品/报刊的排版骨架、圆角控件、柔和精密阴影、轻科技微交互。

## 2. 方向：「合订本」身份底座 + 轻科技精致表层

产品自带报纸骨架（AI 早报 / 概览 / `#N` 编号 / 一期一份）。设计策略分两层：

- **身份层（不被 AI 生成）**：印刷排版的独有结构——页边编号列、细线分隔、钤印、竖排标签、合订本目录。这些是"换掉 logo 也认得出是本产品"的元素，**只此一家**。
- **质感层（AI 产品的精致感）**：统一的圆角与阴影 token、精密的焦点/按压/hover 反馈、tabular 数字、克制的功能性动效。像精心校对的印刷品配了精度仪器。

八字方针：**纸、墨、线、印、号、圆、影、精**。

1. **纸** — 暖白纸底与纸面微渐变（功能性纹理，非彩色 hero 渐变）。层级靠纸张深浅，正文内容不上阴影。
2. **墨** — 近黑墨字，层级靠字重字号；链接下划线；强调色做**细线、钤印、焦点态**等精确用途，不做大面积色块。
3. **线** — 1px 细线承担条目分隔与表头划线；内容块不画完整边框。
4. **印** — 公司与品牌徽章用**方形钤印**（带 2px 微圆角），替代 pill——这是身份元素，不是禁用圆角。
5. **号** — `#N` 为页边大号细体数字列，是排版主角而非标签。
6. **圆** — 圆角按体系用：**浮层与控件**（弹窗/输入/按钮/菜单）用统一圆角 token；**内容排版块**用 0-2px 直角感维持印刷骨架。
7. **影** — 分层阴影 token：静态内容无阴影；**浮层**（合订本弹窗、tooltip、下拉）用「2 层柔和阴影 + 1px 低对比边框」的精密投影，替代单层 `shadow-lg`。
8. **精** — 4px 间距网格、tabular-nums 数字、精确 focus ring（2px offset 单色）、按压 scale(0.98)、定制缓动 `cubic-bezier(0.2, 0, 0, 1)`。

## 3. 设计 Token（在现有 6 主题体系上追加）

6 套主题（data-theme + CSS 变量）保留，只变配色与字体，全部继承以下形状/质感规则：

```css
--rule: color-mix(in srgb, var(--fg) 18%, transparent);  /* 细线色 */
--seal: var(--accent);             /* 钤印色 = 主题强调色 */
--radius-control: 6px;             /* 按钮/输入/菜单/小标签 */
--radius-overlay: 10px;            /* 弹窗/浮层 */
--radius-content: 2px;             /* 内容排版块（近直角的印刷感） */
--shadow-overlay: 0 1px 2px rgb(0 0 0 / 0.04), 0 8px 32px rgb(0 0 0 / 0.10);
--shadow-edge: inset 0 0 0 1px color-mix(in srgb, var(--fg) 8%, transparent);
--ease-out: cubic-bezier(0.2, 0, 0, 1);
--dur-fast: 150ms; --dur-slow: 250ms;
```

- 禁用（通用件黑名单）：`rounded-full` 徽章、`shadow-sm` 默认卡片、`animate-pulse`、emoji 图标、紫色系渐变 hero。
- 数字一律 `font-variant-numeric: tabular-nums`；图标统一 1.5px stroke 细线风格，全站一套来源。
- cyber 主题收敛为"终端打印纸"：暗纸底 + 单一荧光强调，去 glow 去渐变。

## 4. 交互元素规格

### 4.1 报头 Masthead（全站共用 Header）

- 左：品牌**方印**——正方形钤印（2px 圆角）内单字「橘」，旁边站名横排。
- 中：Nav 三联「日报 / 事件流 / 公司」宽字距栏目名；激活态 = 3px 墨线 + 文字转正黑；hover = 墨线以 `--dur-fast` 从左展开。
- 右：刊号（`第 N 期 · YYYY-MM-DD`，tabular-nums）+ 图标按钮组（6px 圆角、hover 纸面加深、focus ring 精确）。
- 报头底边 1px 细线；阅读进度为报头下 2px 墨线。

### 4.2 条目 Item（/stream 与公司页复用，核心组件）

内容排版块（`--radius-content`，近直角），由细线划开，**不用默认卡片盒**：

```text
──────────────────────────────────────────   ← 1px 细线
 #3 │ OpenAI 称误路由 5.5-mini 问题已修复并致歉 ↗   ← 页边编号 + 衬线标题
要闻 · 08-27                                      ← 元数据行
    摘要文字 15px / 1.7 行距 ……
    相关链接 4 · [印][印]                          ← 脚注行：链接数 + 公司钤印
```

- 左栏 48px 放 `#N`：18px / weight 300 等宽数字；无主链接条目（同日后续）显示 `·`。
- **公司钤印**：18px 方形（2px 圆角）；单字取公司名首字，hover tooltip 用浮层阴影 token。**主次语言（spec09 裁决回填后，ADR-0015）**：主导 primary = 20px 实印（加大）、参与 partner = 18px 实印、提及 subject = 16px 描边小印，tooltip 带角色词（「xx · 主导/参与/提及」）；单家归属或未裁决条目维持等尺寸一行（18px 实印）。
- **微交互**：hover 背景变 `--bg-warm` + 左侧 2px 墨线自上而下展开（150ms）；编号数字同步转 accent 色——反馈是"被读到"的印刷感，不是上浮阴影。
- 整卡可点击跳原期，focus 态 = 2px offset accent ring。

### 4.3 索引 Facet 栏（/stream 左侧）

- 分组标题（公司/分类/时间）竖排小字 + 右侧细线，中缝目录感。
- 选项：文字行 + 墨点状态（`●`/`○`），hover 行背景 `--bg-warm`（6px 圆角高亮条，非 pill）；计数用 tabular 小数字右对齐。
- 日期范围：圆角控件 token 的内联输入，focus 时底线 2px accent。
- facet 变化写 URL（ADR-0012）；激活项在报头下显示带 6px 圆角的清除标记。

### 4.4 合订本日期索引（日历弹窗重设计）

- 浮层：`--radius-overlay` + `--shadow-overlay` + `--shadow-edge`，250ms 淡入 + 4px 上移（`--ease-out`）。
- 按月分节，左侧竖排月份「二〇二六年八月」，右侧裸数字网格；当前阅读期数字上压小方印。
- 月份/日期切换有 20ms 逐项 stagger 淡入——精密而不花哨。

### 4.5 骨架（替代 animate-pulse）

- 结构同构的轮廓块（标题条/正文行/页边编号位，`--radius-content`）+ **墨迹扫过**动效：2.4s 一次的低对比斜向高光扫过（自定义 keyframes，非默认 pulse）——保留"加载中"的科技生命感，但动效是本产品定制的。
- 左下角竖排小字「排版中 …」。

### 4.6 空态与错误

- 竖排短语（「无如是期」/「未有所获」）+ 一行说明；重试为下划线文字链，focus ring 精确；无插画无 emoji。

### 4.7 公司 Logo 印（§4.2/§4.4 钤印的素材升级，非形态变更）

- 钤印仍是方形 chip（2px 微圆角与尺寸体系沿用 `.seal`）：命中真实 logo 时（`LogoSeal`）渲染 `object-contain` 的 `<img>`——纸底（`--bg`）+ 1px 细边（`--rule`）+ 内边距，logo 不顶边。
- 无 logo、或 img 加载失败（onerror）的公司回退现有首字方印（实心/描边语义不变）。
- 素材离线拉取至 `public/logos/`（`npm run logos:fetch`，映射在 `src/lib/logos.generated.ts`），运行时不请求第三方；品牌「橘」方印（§4.1）不参与，仍是站点自己的标。

### 4.8 数据面板（/dashboard，spec08）

- **图表语言**：零图表库，全部内联 SVG/CSS 自绘，一律纸底墨线——折线 1.5px 单色墨（`--fg`）+ 数据点圆点、末点转强调色；墨条复用 `.dist-*` 行语言（分类全量 / 公司 Top12，公司行内嵌 LogoSeal 小印）；环形占比三段定死三色：ok=墨（`--fg`）/ missing_owner=朱橙（`--accent`）/ pending=弱化灰（`--fg-muted`），`stroke-dasharray` 分段，禁渐变禁彩虹；热力图 ok 格=墨色深浅按当日条数 4 档（`color-mix` 20%/45%/70%/100%，当日无条数按最低档），`fetch_failed`/`parse_failed`=朱橙，无记录=空格。
- **tooltip**：`data-tip` 浮层泛化为 `.has-tip`（HTML 元素 hover 显示，视觉与 `.seal[data-tip]` 同款；元素须自持定位上下文）；SVG 图形内元素不支持 `::after`——环形段用同款视觉的受控浮层（hover 段、锚定段中角）。
- **交互**：折线数据点与墨条行可点击跳转（`/?date=` / `/stream?category=` / `/company/<id>`）；环形段不做跳转（事件流暂无状态筛入口）；热力图近 12 周（列=周、行=周一至周日，末列=本周，84 格全渲染）仅展示不跳转。
- **数字**：全部 tabular-nums；总览五块用 `.stat-num`/`.stat-label` + `rule-t` 分隔；最近同步附相对时间（挂载时算一次，不做定时刷新）。
- **空态与守卫**：访客进页 = §4.6 竖排空态 + AdminGate 原地验证解锁（无需跳转）；加载失败 = §4.6 错误态 + 重试文字链。

### 4.9 审核工作流（/review，spec10）

- **待审/已决视觉语言**：条目行以「页边编号 + 状态点」起头——待审 = 朱橙点（`--accent`）+ 竖线区小字「待审 · <llm_model>」，已决（人工编辑终版，`llm_model='human-edit'`）= 墨点（`--fg`）+「已决」。点为 9px `●`，只做状态标记不做按钮；暂存期整段仍走印刷骨架（day-head + 细线），不因工作流属性改用卡片盒。
- **徽章主次**：解析建议行以「现状 / 建议」并排对比——现状 = 钤印原样（role 未定 → `grayscale(1) + opacity .55` 灰显）；建议 = 钤印 + 主次小徽章（`--radius-control`）：`primary 主导` 用强调色实底（accent 底 + 纸色字，与「实心印=主公司」同一语义），`partner 合作`/`subject 被报道` 弱化为 `--tag-bg` 底 + `--fg-muted` 字。不发明 pill，不引入新配色。
- **编辑控件**：只复用既有语言——归属行 = 钤印 + 公司名 + 原生 `select`（`.control-input` 收窄变体）+「移除」文字链；「新增归属」= `.control-input` 搜索 + `.overlay-panel` 浮层下拉（`.facet-row` 行）。变更即提交（PATCH），行内 `aria-busy`，失败回滚 + `--accent` 一行错误；primary ≤1 由前端先拦（他行自动让位），不弹确认框。
- **发布确认的反馈形态**：底部 sticky 细线条（纸面 blur + 上缘 1px 细线），期勾选用原生 checkbox（`accent-color: --accent`）默认全选；「确认入库 · N 期」为强调色实底小按钮（印章语义，`--radius-control`）。成功 = 细线小条「● 入库 N 期 · M 条」约 5s 自散，失败 = 一行错误 + 重试文字链——全部复用报头同步反馈语言（§4.1 sync strip），已发布期重拉后自然消失，不做庆祝动效。

## 5. 动效规则

| 场景 | 规格 |
|---|---|
| 通用缓动 | `--ease-out`；入场 `--dur-slow`，反馈 `--dur-fast` |
| 视图切换 | 内容 250ms 淡入 + 4px 上移 |
| 卡片列表入场 | 20ms/项 stagger 淡入（首屏 ≤12 项，滚动加载不做 stagger） |
| hover/按压 | 背景 150ms；按压 scale(0.98)；墨线展开 150ms |
| 浮层开关 | 250ms 淡入淡出 + 4px 位移，无缩放弹跳 |
| 骨架 | 定制墨迹扫过 2.4s 循环 |
| 禁用 | animate-pulse、bounce、marquee、glow、彩色渐变动画 |

## 6. 反通用验收清单（spec 04 截图核对用）

每个组件过三问：

1. **身份**：换掉 logo 还能认出是本产品吗？（页边编号列 / 钤印 / 竖排标签 / 细线分隔至少命中两项）
2. **非默认**：这个组件是否可能原样出现在任何 AI 生成的页面里？（若能，重做）
3. **精度**：焦点态、按压态、空态、数字对齐是否都做了定制处理？

### 4.10 阅读时间线（/，spec11）

- **形态**：内容列左缘的固定竖向刻度轨（ZCode 会话时间线同款语言）——当期每个条目一枚 12×2px 短横（圆角 1px，`--fg-muted` 35% 透明），轨道高 `min(420px, 60vh)`、垂直居中、刻度均匀分布；仅 `lg+` 视口渲染（窄屏与内容列重叠）。
- **交互**：hover 刻度 → 左向浮层（`.has-tip-left`，视觉同 tooltip、方向朝左）显「#N 标题前 24 字」；点击 → `scrollToId(article-N)` 平滑落位。
- **scrollspy**：滚动时视口 40% 线以上最近的条目刻度转 accent 色、加长到 18px（150ms 缓动）；rAF 节流。
- 刻度是 `<button>`（aria-label 带标题），不与卡片抢焦点；骨架/错误态不渲染。

### 4.11 搜索联想与高亮（spec11）

- **联想下拉**：报头搜索条输入 ≥1 字符即触发（250ms debounce），条下方绝对定位浮层——细线边 + overlay 阴影；每行 = 标题（命中高亮）+ 摘要片段（命中高亮，服务端截取前后约 40 字）+ 右侧日期小字（tabular）；↑↓ 移动选中（`--bg-warm` 高亮行）、Enter 跳选中条目（`/?date=#article-N`）或提交、Esc 收起；竞态防护：仅最后一次请求的结果可渲染。
- **结果高亮**：/stream 结果页 title 与 summary 的命中段包 `<mark>`——`color-mix(in srgb, var(--accent) 18%, transparent)` 底、文字色继承、2px 圆角；组件拆分渲染（Fragment + mark），禁 dangerouslySetInnerHTML；query 为空原样渲染。

### 4.12 审核台（/review，spec12 收件箱化）

- **三态计数状态条**：工具行下 rule-t 细线条（同 sync strip 语言）——「待解析 X · 已解析待确认 Y · 无需解析 Z」三段计数（tabular），由 `categorizePending` 纯函数得出（待解析 = 多家命中无建议或 missing_owner，待解析非零时计数转朱橙）；条目区按同序分组渲染，组标题走 day-head 语言带计数（待解析标题朱橙），组内按日期小节排列，条目行与编辑控件（§4.9）不变；missing_owner 条目行内朱橙小字「候选公司：<name>（待入册）」，与候选公司区（复制 YAML）呼应。
- **解析结果常驻**：「运行解析」响应整体落 localStorage（`juya-last-parse`，单管理员本机动作不做服务端持久化），审核页常驻细线条展示最近一次——时间 / 成功 N 条 · 候选 M 个 · 余量 R（失败 K 条转朱橙）+ 逐条失败「itemId · 原因」清单；余量或失败非零时给「再跑一次」文字链（解析幂等只补漏），新响应整体覆盖旧值后错误清单自然消失。
- **入库预览**：底部发布条按勾选实时显示「将入库：N 期 · M 条（建议生效 K 条 · 无建议 L 条按当前归属直接入库）」——K/L 由勾选期内条目 proposal 有无统计（human-edit 亦算建议生效），useMemo 随勾选即算、不弹确认框；确认按钮带条数「确认入库（M 条）」，数字全部 tabular。
- **同步历史行式**：审核页底部「同步历史」折叠区，默认收起、展开懒加载 GET /api/review/history——行式清单（非表格）：成败点标（ok 墨点 / 失败朱橙，§4.9 点语言）+ 日期 + 同步时间（MM-DD HH:mm，UTC naive 直接截取）+ 条数 + 入库状态（已入库 / 待审核 / 无条目）+ 失败原因（朱橙，truncate + title 全文）；行内「展开条目」按需拉该期公开条目（标题 + 分类 + 归属钤印带主次，§4.9 徽章语言，单开一个期），「查看日报」跳 `/?date=`。不做分页、不做图表。
- **解析作业状态（spec13）**：解析为服务端异步作业，状态落 D1、任何时刻刷新可见——「运行解析」秒回启动（POST /api/parse → `{ started, state }`），运行态一律以服务端 parse 字段为准，`localStorage["juya-last-parse"]` 降级为「最近一次我看到的终态」本机缓存（仅在服务端报 idle / 未交付 parse 字段时兜底展示，文案标「上次解析」+ 缓存语义 title）。轮询驱动：挂载拉一次 pending，`parse.status='running'` → 每 3s 静默重拉（不闪骨架），转入 done/failed 停轮并补拉一次数据（done 且 processed>0 才补拉，新建议落地）；409 命中（另一处已在跑）立即接入轮询并提示「另一处已在运行解析，已接入进度」。运行中：按钮禁用显「解析中 k/M…」，解析区进度行 = 呼吸点标（`.breath-dot`，globals.css opacity 脉冲 1.6s，禁发光/渐变，reduced-motion 关停）+ 进度 k/M + 已用时长（startedAt 起算，前端时钟差容忍：负值截 0，每秒走字）+「刷新页面进度不丢」；服务端 failed 朱橙显原因（首条原因 + 逐条「itemId · 原因」清单 + 重试）；done 显完成摘要（完成时间 / 处理 k/M / 余量 / 失败数），仍有失败或余量给「再跑一次」（解析幂等只补漏）。POST 本身失败（网络/口令）沿用灰字 + 重试语言，与服务端 failed 的朱橙区分。
- **数据流标头（spec13）**：审核台标题之下三段流水线横条（FlowHeader，nav + rule-t 细线条语言）——「① 已同步 · 暂存 N 条 → ② 解析 · 状态 → ③ 已入库 · X 期 Y 条」，计数由 `flowCounts` 纯函数得出：N = pending 暂存条目数；② = parse 字段（running 显「运行中 k/M」+ 呼吸点标、idle 显「空闲」、done 显「已完成」、failed 朱橙「失败」）；X/Y = GET /api/review/history(30) 汇总 published>0 的期数与条数（挂载取一次）。数字全部 tabular；每段为按钮，点击平滑滚动到对应区块（① 条目区顶部 / ② 解析区 / ③ 发布条），预留 sticky 报头高度避免落点遮挡，目标未渲染则静默。
